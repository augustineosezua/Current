Budget period (ROADMAP 1.4, shipped in the mobile app): the budget runs by paycheque, by month or by term. It defaults to paycheque when an income has an upcoming date, otherwise month. Month is the calendar month, paycheque runs from the last payday to the day before the next, and term uses the active term plan's dates; a chosen period with no data behind it falls back to month. Safe-to-Spend counts unpaid bills due on or before max(period end, today + 7 days), overdue unpaid bills always count, and the minimum-spend floor is prorated to the period length.

Picked end date (November 17, 2026): the user can choose a day for the current budget to end. It replaces the period's end and keeps its start, so Safe-to-Spend, the daily number and the bills cutoff all run to that day. It can't be in the past, and once it has passed it is ignored, so budgeting returns to the automatic periods on its own.

Phase 2 rules (November 17, 2026):
- Category limits (2.3) are guidance only. They never change Safe-to-Spend, which already counts bills and goals, so counting limits too would double count. A refund in a category nets off its spending, never below zero. An alert fires once per threshold (90% and over 100%) per budget period.
- Rollover (2.12) counts from the budget period containing the day it was switched on. Each earlier period carries its limit minus its spending, so overspending lowers the next period's amount.
- Taking money out of a goal (2.4) moves it from the savings account back to the main spendable account as a money-in entry filed under Savings, so it never counts as income or spending. The goal's saved amount drops, floored at zero, and a purchase it paid for is linked to the goal.
- Importing (2.5) never moves an account balance: the history in a bank file is already reflected in the balance the user entered. A row matching an existing entry on date, amount and merchant is skipped, one for one.
- AI never does arithmetic. Code parses amounts and dates, decides afford verdicts and answers every Ask Current tool. The model only parses text, picks a tool, or writes sentences from figures it is given, and the app shows those figures beside the answer.

AI is on-device only for now (November 17, 2026). The cloud fallback proxy is built but switched off (`CLOUD_AI_ENABLED = false` in `app/mobile/src/ai/index.ts`), so nothing a user types or asks leaves the phone. On iPhones without Apple Intelligence the AI features say they need it; quick add still fills in from history, and afford verdicts and recap figures still work without the written explanation. The paywall says which Plus features need Apple Intelligence. Turning cloud AI on later requires restoring the cloud AI section of the privacy policy first.

One free chart (November 17, 2026): a line of spending each day for the last 30 days is free and sits on Home right under the daily number, with a button into Insights. Everything in Insights stays Plus: the category ring, running total against last time, spending by day of the week, top places, the 8-week and 6-month bars, and the spending calendar. Charts are drawn with `react-native-svg`. The weekly recap also gets an entry on Activity next to Insights, instead of only opening from the Sunday notification.

Testing tools in release builds, for now (November 17, 2026): `DEBUG_TOOLS` in `app/mobile/src/lib/debug.ts` shows "Pretend Plus is on" and the AI test set in every build, so they work on a phone build. It must be set to false before the App Store build (LAUNCH.md).

Ask Current works without a model (November 17, 2026): on iPhones without Apple Intelligence, or when the model fails, `routeAskQuestion` in core picks the tool from English and French keywords and the app writes a plain reply from the same figures (`askReply` in `src/ai/figures.ts`). The model, when there is one, only does the routing and the wording better. A question that matches no tool gets a line listing what Ask can answer.

Ask Current topics (November 17, 2026): everyday words in a spending question cover groups of categories, whatever the user named them. "Food" counts groceries, eating out, takeout and coffee; "getting around", "fun", "shopping" and "rent" work the same way, in English and French (`ASK_TOPICS` in core). Code decides the categories even when the on-device model routes the question, since the model picks at most one. A specific word that is also a category ("coffee") stays that one category. The answer shows the total and each category's share.

Home number setting (November 17, 2026): Settings > Budget chooses whether the big number on Home is per day (the default) or the whole amount until the budget ends. The line under it is just the other number ("$420 total" or "$35 a day"), and the end date ("till Fri, Jan 8") sits in the card's top right. With nothing spare, the line still says when money opens up instead of showing a second zero.

Ask Current becomes a money assistant (November 18, 2026): on the device, the model runs a loop of up to three tool calls per message over Current's tools (spending, safe to spend, bills, goals, semester money, afford, top places, recent purchases, account balances, log a purchase) and replies conversationally with the chat history. It answers general questions too. Numbers about the user still only come from `core`. Logging a purchase is offered with a Log it button and never saved by the model. It gives general information, not personal advice, on investing, taxes, loans and credit. The assistant never uses the cloud fallback. Each opening of Ask (or return to the app) starts a new chat, and only the previous chat is kept to reopen.
